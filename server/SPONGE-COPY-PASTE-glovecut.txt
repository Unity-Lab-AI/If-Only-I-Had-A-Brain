STEP 1 — REQUIRED (unless the grep above came back non-zero).
         Replace the box's updater with main's copy.
================================================================================

Run as whoever owns /opt/unity-brain (the deploy user, not root, unless root is
what owns it). The brain keeps running throughout — this touches one file.

    cd /tmp && rm -rf ual-selfupd && mkdir ual-selfupd && cd ual-selfupd
    git clone --depth 1 --branch main --filter=blob:none --no-checkout \
        git@git.unityailab.com:UnityAILab/If-Only-I-Had-A-Brain.git repo
    git -C repo checkout main -- deploy/self-update.sh

    # validate BEFORE installing — same two checks SELFFIRST itself uses
    bash -n repo/deploy/self-update.sh && \
    bash repo/deploy/self-update.sh --self-test && \
    echo "VALIDATED — safe to install"

    # install by RENAME, never cp/cat over the live path
    cp -p /opt/unity-brain/deploy/self-update.sh /opt/unity-brain/deploy/self-update.sh.bak-fb05ff15
    chmod --reference=/opt/unity-brain/deploy/self-update.sh repo/deploy/self-update.sh
    mv -f repo/deploy/self-update.sh /opt/unity-brain/deploy/self-update.sh

    grep -c SELFFIRST /opt/unity-brain/deploy/self-update.sh   # expect a non-zero count
    wc -l /opt/unity-brain/deploy/self-update.sh               # expect 1571

⚠ mv, not cp. bash reads a script by byte offset as it executes; overwriting a
running script in place makes the shell resume at its old offset inside NEW text
and execute whatever fragment is there. mv replaces the directory entry and
leaves any running process on the old inode. (That trap is documented in the
script itself — I did not discover it, I am repeating it so nobody "simplifies"
this line.)


================================================================================
STEP 2 — RECOMMENDED, NOT REQUIRED. Pre-build the converter.
================================================================================

If you skip this, the press will install a minimal Rust toolchain into the
service user's ~/.cargo (one time, ~200 MB) and build the tool itself. That works,
but it needs two things rustup does NOT provide:

  • a C linker — Rust links with cc. Without build-essential the toolchain
    installs fine and the BUILD fails with a linker error that never mentions
    the linker as the cause. The new script now checks and says so in one line,
    but it still cannot fix it.
  • a writable $HOME for the service user, for ~/.cargo and ~/.rustup.

Either satisfy those:

    sudo apt-get install -y build-essential
    # and confirm the service user has a real, writable home

…or dodge the whole branch by handing the press a finished binary:

    cd /tmp && rm -rf ual-glove && git clone --depth 1 --branch main \
        git@git.unityailab.com:UnityAILab/If-Only-I-Had-A-Brain.git ual-glove
    cd ual-glove
    cargo build --release -p unity-weights --bin unity-glove
    mkdir -p /opt/unity-brain/bin
    install -m 0755 target/release/unity-glove /opt/unity-brain/bin/unity-glove
    /opt/unity-brain/bin/unity-glove --help      # sanity

The press looks for /opt/unity-brain/bin/unity-glove FIRST and skips the
toolchain install entirely if it is there.

⚠ /bin and /.cargo-target were added to the overlay's exclude list in this same
change, so rsync --delete will not wipe either on future presses. Without that
exclude the "second press costs nothing" claim would have been false — worth
knowing that I checked rather than assumed.

⭐ You can also build the table yourself right now and the press will find it
already current and do nothing:

    /opt/unity-brain/bin/unity-glove ensure \
        /opt/unity-brain/corpora/glove.6B.300d.txt \
        /opt/unity-brain/corpora/glove.6B.300d.bin

    # ~4 s, writes ~485 MB. Optional full check (~5 s, reads the text back):
    /opt/unity-brain/bin/unity-glove verify \
        /opt/unity-brain/corpora/glove.6B.300d.bin \
        /opt/unity-brain/corpora/glove.6B.300d.txt

================================================================================
THINGS I DID WRONG THAT ARE WORTH KNOWING
================================================================================

1. The first draft of the JS reader wrote the header length as 36 bytes instead
   of 8+4+4+4+4+8+8 = 40. Every field landed four bytes early. It loaded 400,000
   vectors at the right dimension, REPORTED SUCCESS, and scored ~0.00 cosine
   against the real table on every probe word. An off-by-four in a binary reader
   does not fail, it lies. The length check is exact equality now, which catches
   that with no harness at all.

2. The original "bit-exact" verification proved less than it sounded: the
   verifier used the converter's own f32 accumulation, so it compared the code
   against itself. The real check runs the shipped loader (from
   git show HEAD:js/brain/embeddings.js) against the new one over the whole
   table — 400,000/400,000 identical, 0 differing, 0 missing, 0 extra.

3. Format v1 did not pad the vocabulary, so the matrix started at offset 2 mod 4.
   Invisible to Rust (from_le_bytes does not care) and fatal to
   new Float32Array(buf, off, n), which throws unless the offset is 4-aligned.
   v2 pads. A format decision that is free in the language that WRITES the file
   can be the entire cost in the language that READS it.

4. I first tested by running node server/brain-server.js by hand — wrong cwd,
   wrong heap flags, no control plane, and DREAM_NO_AUTO_GPU unset so it tried to
   auto-launch a browser donor. Gee caught it. Re-running through the real
   launcher is what exposed the 862 MB re-download in item 3 of the change list.
